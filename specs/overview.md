# React・Express・テスト学習アプリ 仕様書

ステータス: 初版仕様を具体化済み。詳細は application.md・curriculum.md・server.md を参照。

## 目的

タスク管理アプリの段階的な実装を通じて、Reactの主要Hooks、ExpressによるAPI開発、VitestおよびUIテストの基礎を学ぶ。
学習者がプロダクトコードを書き、UIの変化を確認した後に、その振る舞いを立証するテストを追加する。

## 合意済みの構成

### 実装課題とタスク管理アプリ

- 学習開始時点では画面の枠と課題を用意する。
- 課題の対象となる機能は、学習者が自分で実装する。
- 各課題に要件を記載し、期待する振る舞いを確認できるようにする。
- 機能の実装結果をタスク管理アプリのUIで確認できるようにする。
- プロダクトコードの実装後、学習者がVitestやUIテストを追加し、要件を満たすことを確認する。

### 完成済みのリファレンス

- 実装課題に取り組む際に参照できるページを用意する。
- リファレンスはトグル操作で表示・非表示を切り替えられるようにし、学習者が自分の意思で参照するタイミングを選べるようにする。
- 各課題内に関連するリファレンスを配置し、個別に開閉できるようにする。
- 初期状態は閉じた状態とし、学習者が必要に応じて開く。
- React HooksやExpressのミドルウェアなど、よく使う技術を扱う。
- 構文、用途、動作デモを確認できるようにする。
- Reactでは操作に応じたUIの変化や技術の効果を確認できるようにする。
- Expressではリクエスト、レスポンス、エラー表示などを通じて効果を確認できるようにする。

### コードの編集と動作確認

- 学習者は普段使っているローカルエディタで、このプロジェクトのコードを編集する。
- アプリをローカルで起動し、ブラウザでUIと動作を確認する。

## 学習の流れ

全課題で「要件を読む → プロダクトコードを実装 → UIで動作確認 → テストを追加」の順序を徹底する。
課題の説明と手順もこの順序に統一し、テストの追加はプロダクトコードの実装とUIでの確認後に行う。
リファレンスは必要なときに参照できる補助として扱う。

1. 課題の要件と期待する振る舞いを読む。
2. 必要に応じてリファレンスで構文や動作を確認する。
3. 対象機能のプロダクトコードを実装する。
4. UIを操作して実装結果を確認する。
5. VitestやUIテストを追加し、要件どおりの振る舞いを検証する。
6. 次の課題へ進む。

## 学習順序

1. Reactだけでタスク管理の基本機能を実装し、主要Hooksの基礎を学ぶ。
2. Expressを導入し、API・データ保存とフロントエンドの連携を学ぶ。

両段階とも各課題で上記の学習の流れを守り、テスト学習を最後にまとめて行う構成にはしない。
対象技術の詳細と課題の分割は今後決定する。

## 学習者と難易度

- 学習者の開発経験は約2年を想定する。
- 基礎から体系的に学び、徐々に難易度を上げる構成にする。
- 一つの機能についても「基礎」「中級」「ナイトメア」の段階を設け、実装を発展させながら学べるようにする。
- 各段階で改善の目的と効果を説明し、UIの動作や観測結果を通じて確認できるようにする。
- 各難易度でも「要件を読む → 実装 → UIで確認 → テストを追加」の順序を徹底する。
- まず各機能の基礎課題を一巡して動くアプリを作り、その後、中級、ナイトメアの順に同じ機能を深掘りする。
- 基礎課題はReactだけで動く基本機能から始め、その後ExpressによるAPI・データ保存との連携へ進む。
- 各課題ではテストの追加まで終えてから次の課題へ進む。
- 難易度ごとの具体的な到達目標は今後決定する。

## 確定した実装範囲

- タスクの追加・一覧・編集・削除、完了切替、検索・絞り込み・並替、期限・優先度、API保存取得・通信状態を課題にする。
- React・Express・参考コード・テストはすべてTypeScriptで統一する。
- 学習基盤と完成済みの参考例を実装し、課題のプロダクトコードとそのテストは学習者が追記する。
- 仕様書 → 実装 → テスト → レビュー → Notion「学習アプリ開発」に記録する。
