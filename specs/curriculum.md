# 学習カリキュラム

## 共通の進め方

全18課題を基礎6課題 → 中級6課題 → ナイトメア6課題の順に進める。各課題で必ず「要件を読む → プロダクトコードを実装 → UIで動作確認 → テストを追加」を完了してから次へ進む。完了記録は学習者の自己申告であり、テスト実行や採点を自動で保証しない。

React・Expressの実装、リファレンス、追加するテストはすべてTypeScriptを使用する。

学習者はローカルエディタで `src/exercises/TaskWorkspace.tsx` と `server/exercises.ts` を編集する。学習用の枠と独立したリファレンスは提供するが、タスク管理の完成実装や課題の完成テストは提供しない。UIテストは Testing Library による振る舞いの検証を基本とし、ブラウザ横断のE2Eは発展課題とする。

## 段階と到達目標

| 段階 | 課題 | 到達目標 |
| --- | --- | --- |
| 基礎 | 追加・一覧、編集・削除、完了切替、検索・並替、期限・優先度、API保存・取得 | Reactの状態とイベントを理解し、APIとつながる小さなアプリを完成させる |
| 中級 | reducer、Context、入力とフォーカス、非同期検索、計測と最適化、ミドルウェア | 状態管理、アクセシビリティ、通信、責務分離の改善効果を説明する |
| ナイトメア | Undo、楽観更新、競合・中断、応答性、保存競合、障害復旧 | 連続操作、遅延、失敗、競合条件下でもデータとUIの整合性を保つ |

主要Hooksとして useState / useEffect / useRef / useReducer / useContext / useId / useMemo / useCallback / useDeferredValue / useTransition を扱う。独自Hookも中級以降で扱う。useMemoとuseCallbackは計測で必要性を判断し、追加自体を成功条件にしない。サーバー機能に依存するHooksなど、すべてのReact APIの網羅は初版の対象外。

## データとAPIの学習契約

タスクは id、title、completed、dueDate（未設定可、YYYY-MM-DD）、priority（low / medium / high）を持つ。基礎の保存はサーバープロセス内のメモリでよく、再起動で消えることをUIと説明に明記する。永続DBは初版の必須条件にしない。APIは `/api/tasks` のGET・POSTと `/api/tasks/:id` のPATCH・DELETEを学習者が実装する。空白だけのタイトルは受理しない。

発展課題では version と更新競合、リクエストID、入力検証、共通エラーハンドラーを導入する。Expressの効果はレスポンスの状態、エラー表示、リクエストの流れで観測する。教材のミドルウェアデモは起動中のExpressに実際にリクエストを送り、HTTP状態・処理順・リクエストID・経過時間を表示する。

## リファレンス

各課題に独立した開閉トグルを置き、初期状態は閉じる。構文例はカウンター・テーマ・独立した通信などの小さな題材とし、課題の完成解答を表示しない。開閉状態はセッション中の表示状態として扱い、永続保存は必須にしない。

課題ごとの具体的な要件、UIでの受け入れ確認、後から追加するテストの観点は `src/data/curriculum.ts` を正本とする。要件・確認項目・テスト観点は順序と目的を分けて表示する。
