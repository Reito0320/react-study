# 課題テストの進め方

要件を読む → プロダクトコードを実装する → UIで確認する → テストを書く、の順に進めます。

- React課題（チャプター1から）: `src/exercises/chapters.test.tsx`
- Express課題: `server/exercises.test.ts`

章ごとにdescribe、最低限の要件ごとにit.todoを用意しました。対象のit.todoをitに変え、第二引数にテスト本文を書きます。章名の `[basic-02]` と要件名の `[basic-02-01]` は画面との照合に使うため残してください。追加のテストは自由に書けます。IDのないものは「追加で書いたテスト」に表示します。

```sh
npm run test:learning -- basic-02
npm run test:learning
```

1行目は指定章、2行目は全課題です。開発サーバーを `npm run dev` で起動しておくと、要件ごとの結果が画面に自動反映されます。未実装・スキップ・未検出は成功ではありません。空のitは成功してしまうため、本文には実際の操作とexpectを記述してください。コードを変更したら再実行します。

`npm test` は学習基盤も含めて検証しますが結果パネルは更新しません。UIテストは `npm run test:e2e`。Vitestの構文解説はチャプター0を参照してください。

## テスト名と画面の自動同期

上記2ファイルの `describe('[basic-02] …', ...)` と `it` / `it.todo` / `test` の文字列タイトルを保存すると、約3秒以内に右側の項目名・追加・削除が反映されます。別の要件一覧ファイルを編集する必要はありません。IDは章に対応した一意のものにしてください。実行結果は引き続きコマンドで更新します。保存だけで成功にはなりません。

現在は直接記述した文字列・補間なしテンプレート文字列が対象です。変数で組み立てたタイトルや `it.each` の生成項目は一覧抽出の対象外です。IDなしの追加テストは実行後に表示します。構文エラーやID重複は画面にエラーを表示します。

## 任意の挑戦

右側の「任意：そのテスト、不具合を見つけられる？」を開くと、実装に小さな不具合を一時的に入れ、テストの検出力を試せます。元の実装を保存し、検出を試したら必ず戻して再実行します。学習の完了条件には含まれません。
